02 CAPABILITIES / MODULES

一份上下文，
五个工作模块。

资料、智能体、编辑器连接和运行观察共享同一份项目上下文。每个模块都能单独使用，也能串成一条完整的工作链。

01 / PROJECT MATERIALS

项目资料，不再是散落的文档。

规范、实体、组件、设定、地图与 UI 各自成文，保留父级、继承和组件绑定。文件就是数据源，版本和引用都能被检查。

  • → Markdown / YAML，直接存在项目里
  • → 实体层级、组件字段与引用校验
  • → 页面、智能体与工具共用同一套资料
PATH specs/entities/FORMAT MD + YAML
02 / AGENT RUNTIME

智能体知道自己在哪个项目里。

会话自动携带项目资料、Skills、MCP 和编码工具。读取、修改、验证都围绕当前项目发生，而不是从零解释背景。

  • → 项目上下文按需注入
  • → 工具调用与审批可见
  • → 每轮结束附文件变化清单
03 / GODOT BRIDGE

从编辑器，到运行中的游戏。

集中查看与启停 Godot EditorPlugin；启用截图桥后，智能体可以读取运行中的游戏视口，检查真实画面而不是猜。

  • → EditorPlugin 安装与启停
  • → 运行视口截图
  • → 场景、节点与资源检查
04 / OBSERVABILITY

模型请求，有迹可循。

按诊断编号查看请求阶段、重试与响应记录，定位连接问题；执行过程中的公开进度和工具步骤按顺序展开。

  • → 模型诊断日志
  • → 公开进度气泡
  • → 工具调用与结果记录
05 / MULTI-WINDOW

多个项目，各自保持上下文。

通过 Trailblazer Hub 打开多个 SpecLoom 工作区。切换项目时，每个窗口保留自己的会话、草稿与运行状态。

  • → Hub 模块多开
  • → 项目级会话隔离
  • → 独立窗口并行运行

03 PROCEDURE / 3 STEPS

先读现场，再动手。

不需要先写一份完美的说明。打开项目，SpecLoom 会沿着资料和代码把上下文串起来，再由你决定下一步。

01 $ specloom open ./project

选择项目

打开已有的 Godot 项目或普通代码项目。SpecLoom 读取项目结构、资料目录与已配置的工具。

OUTPUT — PROJECT LOADED
02 $ context --read

读取项目上下文

规范、实体、组件、Skills 与 MCP 进入同一份上下文。智能体先理解项目，再提出改动建议。

OUTPUT — CONTEXT READY
03 $ run --review

执行并检查改动

推进任务、查看工具步骤与本轮文件变化。需要审批的写入仍然由你确认。

OUTPUT — CHANGES REVIEWED
