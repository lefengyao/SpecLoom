# SpecLoom

智能体可以直接管理应用内资料，操作成功后实体、组件等页面自动刷新。查询与读取工具初始可用，其余通过 `ToolSearch` 查询“资料”或工具名称加载：

| 工具 | 用途 |
| --- | --- |
| `MaterialsList` | 按分类、关键词、分组查询，分页返回摘要和版本 |
| `MaterialRead` | 读取结构化资料、正文和版本 |
| `MaterialCreate` | 按名称创建实体、组件、地图、设定、UI 或规范 |
| `MaterialUpdate` | 修改名称、说明、分组、父级、继承、字段或正文 |
| `MaterialBindComponent` | 挂载／更新组件，填充默认值并检查字段类型 |
| `MaterialUnbindComponent` | 移除组件绑定 |
| `MaterialSetImage` | 从项目相对路径导入配图、复用已有图片或清除配图 |

更新工具需要 `expectedVersion`，使用 `MaterialRead` 或前次保存返回的版本。`MaterialUpdate.changes` 中 `group`、`parent`、`extends` 传 `null` 可清除。配图支持 PNG/JPEG/WebP/GIF，最多 2 MiB。智能体保存与页面保存共用校验；自动刷新保留未保存草稿，版本冲突时可选择重新读取。

本地桌面智能体开发工作区，以 Godot 为首个引擎方向，也支持普通代码项目。规范、实体、提示词和决策保存为 Markdown/YAML；每个会话都能使用编码工具、项目 Skills 和配置的 MCP。

## 运行

需要 Node.js 22.12+、npm 和 Windows 桌面环境。编码工作集中的 Bash 使用宿主 shell，Windows 默认 PowerShell，也可选择 Git Bash；旧审查工具的隔离命令与 Godot 验证需要 Docker。桌面控制当前支持 Windows。

```powershell
npm install
docker pull bash:5.3@sha256:61962062d969cb46dfc2bad061d36342406fa485f64f246aa7e95693ca07df1f
docker pull barichello/godot-ci:4.4.1@sha256:274a9a1849ec64d0ce8577ccf698bd1b97f9994c150a8e9783e561533e568708
npm run dev
```

开发启动器自动选择可用端口并打开 Electron。Windows 上运行 `npm run build` 同时生成安装包和便携 ZIP，版本号自动读取 `package.json` 的 `version`，所有打包输出按版本保存在 `release/<版本号>/`，不同版本各自保留。当前 0.1.4 的 x64 产物为：

- `release/0.1.4/SpecLoom-0.1.4-Setup-x64.exe`：安装向导，可选择安装目录。
- `release/0.1.4/SpecLoom-0.1.4-Portable-x64.zip`：完整解压后运行其中的 `SpecLoom.exe`，无需安装。

测试和日常调试使用 `npm run dev` 与 `npm run test:e2e`，直接运行源码；开发入口转译与 Vite 缓存放在系统临时目录，关闭后回收。测试不执行图标生成、生产 Renderer 构建或 Electron 打包，不更新 `dist/` 和 `release/`。旧差异审查的 Godot 验证仍使用 4.4.1 容器；游戏与编辑器截图现由官方 Godot MCP 插件提供，集成运行验证目标为 Godot 4.7 或更新版本。

源码版默认复用安装版的用户数据目录，供应商、密钥和近期项目随重启保留。Windows 启动器在本机共享可访问时使用真实安装版目录，避免桌面应用宿主将 Roaming 重定向到自己的 LocalCache；共享不可访问时使用标准用户目录。显式设置 `SPECLOOM_USER_DATA_DIR` 可使用独立的调试目录，Electron 验收测试始终指定临时目录。

启动器还会在 Electron 启动时传入同一目录的 `--user-data-dir`，保证加密密钥的上下文与供应商配置一致。模型流式请求按等待新数据的时长判断超时，持续思考和保活消息不会消耗固定的整轮计时额度。DeepSeek 中断排查和验证记录见 [排查报告](docs/model-interruption-2026-10-08.md)。

会话详情在展开时才加载正文，历史 Markdown 不随其他消息更新重复解析；流式响应的协议开销与正文分别限制。性能对比、草稿恢复和响应大小回归见 [会话性能记录](docs/chat-performance-2026-10-08.md)。

0.1.4 支持 Hub 模块多开：窗口可独立选择项目，同项目共享会话与后台，关闭其中一个窗口不会中断其余窗口仍在查看的项目。供应商和全局设置同步，窗口草稿与待引导消息分开保留。见 [0.1.4 发布记录](docs/release-0.1.4.md) 和 [模块安装说明](docs/trailblazer-hub-module.md)。

0.1.3 保留已访问页面，支持左侧导航收缩、官方与自定义组件分类、工具链方框及右侧栏，并提供不中断当前回复的智能体引导消息。功能和验证记录见 [0.1.3 发布记录](docs/release-0.1.3.md)。

0.1.2 进一步减少长对话更新时的历史序列化与工具记录重复扫描，并修复删除会话后迟到的保存结果使会话重新出现的问题。本版同时包含五次断流重试、取消工具轮次上限、输入框发送后清空及三种工具审批权限。优化与验证记录见 [0.1.2 发布记录](docs/release-0.1.2.md)。

离线文档启用后，智能体通过 `ToolSearch` 加载 `OfflineDocsList` / `OfflineDocsRead`，按需读取。`OfflineDocsRead` 支持 `offset` 和 `limit`，默认从 0 开始、每页最多 6000 字符，`limit` 最大 8000；实际页长会根据 JSON 转义后的工具输出预算缩短，正文与续读信息完整返回。结果中的 `page.hasMore=true` 表示还有后文，下一次读取应使用返回的 `versionId` 与 `page.nextOffset` 作为 `offset`，直到 `hasMore=false`、`nextOffset=null`。偏移按 UTF-16 计数，直接使用返回值可避免拆开表情字符。

分页读取会先对完整正文脱敏，再划分页边界；应用内的直接预览仍返回全文。当前文本解析上限仍为 1 MiB，二进制或超出该上限的文件只返回元数据；分页不改变单次智能体运行的上下文限制。

## 品牌资源

官方配色为「纸墨」：纸白 `#edf1e8`、墨绿 `#14352a`、织绿 `#1f6f54`、赭金 `#a9762e`。应用默认外观为「纸墨」主题 + 「织绿」主题色，可在“设置 → 外观”切换；已有本地偏好不会被覆盖。官网 `website/` 是这套配色的参考实现。

吉祥物为绿色独眼精灵「络络」（Thread Sprite，倒置、无侧边附件）。它从 `specs/` 里的项目线索出发，为图纸拉线。顶部品牌标识与欢迎页使用 `src/renderer/Mascot.tsx` 的内联 SVG，欢迎页显示名字并播放眨眼、呼吸、张望动画，瞳孔会跟随鼠标，哑光实心绿球沿倾斜轨道做三维环绕、后半圈绕到身后并拖出尾迹；内置线团/宽摆/高抛三条轨道，欢迎页每 20 秒轮换，原来的白色笑弧轻微开合；旁边的气泡会按时段问候，点一下换一句（`MascotSpeech.tsx`）；`prefers-reduced-motion` 时动画静止。窗口与应用图标仍从 `src/renderer/public/brand/specloom.svg` 生成。`npm run build:icons` 会生成透明 PNG、Windows 多尺寸 ICO 与 macOS ICNS；应用构建会自动执行。Windows 构建保留图标和版本资源编辑，仅跳过代码签名。

配色、吉祥物与动效的完整规则见 [品牌规范](docs/brand.md)。

图标生成使用 Playwright Chromium，首次构建前运行 `npx playwright install chromium` 安装浏览器。

## 项目流程

1. 打开现有项目目录，或创建内置的“灯塔守望”示例；没有 `project.godot` 的目录按通用工作区打开。
2. 在项目资料中整理规范、实体、组件、设定、地图和 UI。新建实体只需填写名称，再在详情中填写说明、选择父级与继承原型、挂载组件；每份资料保持独立文件。
3. 在“供应商”页面添加多个供应商，选择 `openai`、`anthropic` 或 `gemini` 协议，填写服务地址和 API 密钥；进入供应商的模型管理后可拉取、搜索、批量添加或手动添加模型，并配置思考、图片、上下文、输出上限及完整 JSON v1。无密钥的本地服务可以显式保存为空密钥。
4. Skills 页直接显示项目工作流，不需要先新建会话；MCP 页点击“添加 MCP”后填写配置，保存成功或取消后收起表单。新建会话后可查看实际可调用的编码工具、MCP 和引擎插件。
5. 直接输入开发要求。智能体通过 `Read` 获取版本与内容，再用 `Write`/`Edit` 修改；通过 `ToolSearch` 按需加载长任务、子智能体、桌面控制等工具。
6. 原有“新建任务”用于需要暂存差异审查的流程；其 `files.*`、`changes.*` 仍保留摘要审批与版本保护。内置编码工作集直接操作项目，不需要另建任务解锁。
7. 在任务与历史中回看范围、对话、工具事件、变更和验证结果。模型请求失败后可继续同一任务；重启恢复未提交草稿与完整工具批次的有界会话，旧批准、读取凭证与活动草稿的验证授权不恢复。

“实体”“设定”“地图”“UI”“组件”页使用父级资料构建层级树。例如先创建“物品”，再使用“新建子实体”创建“武器”，随后在武器下创建具体装备；分类节点也有自己的资料文件。父级从实际资料中选择，支持继续嵌套；继承自另一个实体与父级分类分别设置。

“组件”独立管理可复用字段，提供空白、生命值、坐标、速度模板。每个字段有名称、显示名称、数值/文本/布尔类型和默认值。实体详情可以添加多个组件，修改该实体的字段值，也可以查看和覆盖从原型继承的组件。组件定义与实体实例的值分开保存。

实体详情还可添加状态机：从“待机”状态开始编辑状态、初始状态和事件转换。状态机基类会在项目初始化时写入 `specs/components/state_machine.md`，实体保存时自动挂载一次；状态机配置由页面、智能体工具和校验器共同验证。

实体、组件、设定、地图与 UI 创建后立即保存到项目，并留在对应资料页。资料浏览器支持搜索、分组筛选和列表／图标切换，不需要展开项目树；已有的父级层级树仍可查看。新建组件可立即被实体引用。

详情中的“分组”可输入新名称或选择已有名称；分组与父级、继承关系分别管理，清空即可移出分组。可上传 PNG/JPEG/WebP/GIF 配图（最多 2 MiB），图片复制到 `assets/specloom/materials/`，资料仅保存相对路径。编辑后点击“保存资料”直接写入文件，不创建智能体任务、不切换到工作区。人工保存检查字段与本次新引入的引用错误，并保留文件版本保护；发生外部修改时保留本地编辑并提示重新读取。未保存的编辑缓冲在当前项目内切换页面时保留，关闭前需要保存。资料页仍可切换“源码编辑”修改完整 Markdown/YAML。

工作区模型下拉框使用 `{ providerId, model }` 引用；供应商模型管理中的“设为默认”会保存全局默认模型，工作区切换模型和“思考偏好”会保存当前会话选择。会话偏好支持继承模型默认、关闭、低、中、高，显式偏好会进入实际协议请求。设置页“智能体”提供 0–100 的稳定性偏好（越高越精准稳定、越低越发散创新，按 temperature = (120 − 偏好值) / 100 转换，独立于逐模型配置）。聊天输入栏展示当前上下文估算：包含系统提示、工具定义和待发送内容，并使用同一模型最近单次请求的实际输入用量校准；悬浮提示分别列出当前估算、最近请求和本轮累计用量。校准随会话保存，切换模型或压缩上下文后重新测量；累计消耗不参与当前占比。默认在模型可用上下文或历史保存容量接近 90% 时先分块压缩历史，再携带摘要与保留内容继续请求。自定义思考映射按协议约束路径：Anthropic 为 `thinking`，Gemini 须以 `generationConfig.` 开头。文本输入框和 JSON 编辑器支持右键复制、剪切、粘贴，也提供快捷键 `Ctrl+C`、`Ctrl+X`、`Ctrl+V`。

设置页“智能体”提供全局个性化提示词与当前项目提示词。全局要求保存在本机设置，跨项目生效；项目要求保存为当前项目的 `specs/prompts/system-prompt.md`，最多 16,000 字符。初始化只创建提示词目录，保留已有文件；文件不存在时视为空提示词。保存后下一次运行立即读取最新内容，切换项目会重新加载。

提示词按“内置系统规则 → 全局要求 → 当前项目要求 → 工作区能力清单”注入。会话统一使用智能体能力；项目提示词保存绑定项目身份和文件版本，遇到外部修改会提示重新加载并保留编辑草稿。修改已有文件前必须读取，不覆盖外部新修改，不将凭据写入对话历史。

现有文件必须先被当前智能体上下文实际读取，才能改写。`VERSION_CONFLICT` 表示文件已被外部修改；保留人工修改，读取最新版本后重新判断变更。旧暂存审查任务的冲突基线不会自动替换。

## 工作区对话

工作区左侧管理独立会话，支持新建、切换、改名、归档、恢复、删除及 JSON 导入导出。草稿、模型与思考偏好按项目和会话保存；切换时后台运行继续，停止保留已收到的回复。同一会话只能同时运行一次，不同会话独立运行。删除会话会移除其聊天历史；关联审查任务的会话保留任务审计与运行检查点，可从历史页重新进入原任务。删除聊天不删除项目文件，导入历史不会恢复任务授权或未结束的问题等待点。

输入栏支持 Enter 发送、Shift+Enter 换行和可选 Ctrl/⌘+Enter 发送，中文输入法确认文字不会误发送。发送失败恢复原草稿，期间新写的文字保持原样；运行中可准备下一条消息。可附加不超过 64KB 的文本文件，或添加资料路径引用；智能体可通过 Read 读取引用。

输入栏的“联网搜索”默认关闭，可选择自动、厂商原生、免费托管或本机自建，选择按会话保存，运行中与归档会话不可切换。开启后直接提供搜索及当前模式支持的网页正文工具；自动模式按原生、免费托管、本机自建回退，厂商原生不提供正文提取。服务地址、原生端点限制、来源引用和正文预算见 [联网搜索](docs/web-search.md)。

OpenAI、Anthropic、Gemini 从供应商到界面的流式文本与工具卡片使用统一时间线。工具参数完整接收并验证后才执行；参数和输出展示脱敏、有界内容，截断会明确标记。AI 回复支持 Markdown/GFM、GDScript 代码及复制。滚动只在底部跟随，向上阅读时显示“回到最新”。

思考期间显示动画和实际运行进度；供应商返回的思考摘要单独展示，模型未返回摘要时显示运行状态。每轮保留调用工具及次数，不再随新一轮覆盖。个性化支持分别上传用户与智能体头像，默认智能体头像使用品牌 Logo。

完整工具、参数和 MCP 配置见 [编码工作集](docs/tool-workset.md)；联网模式和服务契约见 [联网搜索](docs/web-search.md)；Godot 插件安装、工具列表与故障排查见 [SpecLoom Godot MCP](docs/plugins/godot-mcp.md)。

结构化问答支持必填文字、单选、多选、稍后处理和失败重试。回答持久化后恢复同一次运行。问答用于澄清需求，旧暂存审查工具仍使用当前 digest 绑定的差异审查。应用重启后保留历史，并将失去活动等待点的运行标记为中断。

## 数据布局

`specs/project.md` 与 `specs/outline.md` 保存项目规则和大纲；`specs/entities/` 保存实体与分类资料，`specs/components/` 保存组件定义，`specs/settings/`、`specs/maps/`、`specs/ui/` 保存设定、地图与 UI。`specs/tasks/`、`specs/decisions/`、`specs/prompts/` 保存流程资料。项目 Skills 位于 `.specloom/skills/`。内部历史位于 `.specloom/history/`，不能授予智能体写权限。

实体 front matter 示例：

```yaml
schemaVersion: 1
id: fire_goblin
type: entity
title: 火焰哥布林
description: 近战敌人，受到攻击时扣除生命值。
status: draft
version: 1
parent: enemies
extends: goblin
components:
  - id: health
    values:
      current: 80
      max: 80
relations: []
source: developer
```

新建实体默认类型为 `entity`，详情中也可选择 `character`、`enemy`、`system`、`item`、`event`；地图使用 `map`。实体文件名与 `id` 一致，目录可嵌套；资料树按 `parent` 组织，物理目录不决定父子关系。上例要求 `enemies`、`goblin` 是实际实体资料，`health` 是实际组件定义。

组件 front matter 示例，保存为 `specs/components/health.md`：

```yaml
schemaVersion: 1
id: health
type: component
title: 生命值
description: 当前值与生命值上限。
fields:
  - key: current
    label: 当前值
    type: number
    default: 100
  - key: max
    label: 上限
    type: number
    default: 100
```

`parent` 引用同类资料的真实 ID 或路径；`extends` 引用单个实体原型；`components` 引用组件定义，`values` 覆盖已有字段，未覆盖字段使用继承值或组件默认值；`relations` 保存普通实体关联。验证检查缺失引用、父级/继承环、重复组件以及字段与值类型；缺失或循环的父级关系显示在资料树的“关系错误”分支。完整说明见 [分层资料与组件设计](docs/superpowers/specs/2026-10-06-hierarchical-project-materials-design.md)。

源码编辑后可在审查页点击“验证”检查完整资料与引用。人工批准沿用手工审查流程，不代表资料已经通过验证。

项目规则中的 `constraints.maxScriptLines` 和 `constraints.maxSceneNodes` 控制生成预算，默认分别为 250 和 80。

生成清单首版提供初始化和引用校验，实体与生成文件的映射由开发者维护。

API 密钥在应用用户数据目录中通过 Electron `safeStorage` 加密保存，不进入游戏项目，不通过列表返回。模型端点变更需要重新提供密钥或显式选择无密钥访问。供应商公开状态只显示是否有密钥、掩码预览和存储方式；模型 JSON 不包含供应商 ID、模型 ID或密钥。

## 验证与限制

```powershell
npm test -- --fileParallelism=false
npm run typecheck
npm run lint
npm run test:e2e
```

Docker 集成测试在后端或固定镜像不可用时明确跳过；跳过不等于验证成功。Godot 验证检查规范字段、引用、生成预算、无头导入和可选场景冒烟。引擎运行始终使用私有快照、禁网、只读容器根目录、无额外 capabilities 和资源限制。

异常退出后，再次打开项目会回收已确认所有者退出的快照与容器。活跃或存活状态不确定的所有者会保留；清理失败也保留快照与恢复记录，并在工作区显示警告。

单文件替换是原子的。跨文件提交使用串行处理、持久日志和版本保护的恢复；普通文件系统无法对任意外部编辑器保证跨文件事务。恢复遇到外部新修改时会保留文件并报告冲突。

本机 MCP 的地址、临时认证令牌和任务 ID 可在应用中查看。见 [MCP 配置](docs/mcp.md) 与 [架构](docs/architecture.md)。
