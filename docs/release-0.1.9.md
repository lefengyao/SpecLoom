# SpecLoom 0.1.9 更新

本轮落实 2026-10-17 的后续体验反馈：释放聊天高度、修复中文进程通道，并让执行过程和每轮文件变化可以直接查看。最初以源码更新交付；2026-10-18 按用户要求生成 Windows x64 安装版、便携版和 Hub 模块包，包含下方的公开进度气泡修正。产物与验证范围见 [0.1.9 打包验收](reports/2026-10-18-v0.1.9-package-verification.md)。已安装的软件和模块需要手动更新。

## 使用变化

1. 顶部项目信息横栏收进左侧导航。项目名保持可见，点击后展开项目路径、引擎、渲染方式和主场景；导航收起时仍有入口。主区域释放原先整行占用的高度。
2. Windows 进程监督通道明确使用 UTF-8，PowerShell 与 cmd 分别按对应规则传入命令，修复中文路径、中文参数和输出乱码。旧命令输出可按系统代码页解码；真实 Windows 启动错误保留系统错误码，JSON 错误位置不会被误当作系统码。尚未换行的日志会及时显示为可更新的临时片段，避免就绪消息一直藏到进程结束。
3. 聊天按执行顺序交错显示公开进度气泡和工具步骤，最终答复独立呈现。编辑时可以看到文件路径和短修改片段；展开工具框或工具侧栏可查看完整记录。用户向上阅读时不强制滚回底部，可通过“查看最新步骤”返回进度。
4. 每轮结束后显示本次运行的文件清单，区分新增、修改、删除，以及“编辑工具确认”和“运行期间检测”。没有检测到变化也会明确显示；失败或取消的运行保留已经确认的变化。报告保存在会话中，重载后仍可查看。

## 范围与限制

- 公开进度来自智能体实际返回的普通文字；提示词要求在操作前、实际发现、阶段变化或阻塞时简短说明，不额外调用模型生成过程。供应商推理保留为可选详情，默认折叠。接收中的未验证工具参数不直接显示，失败或取消的编辑不会展示成功修改片段。
- 文件报告以本轮开始时的内容为基线，使用有界内容摘要比较，不依赖 Git，不把运行前已有的脏文件自动计入本轮。默认每次扫描最多 600ms、4000 个文件、12000 个目录项、32MiB 内容，单文件上限 2MiB；取消时缩短比较时间。
- 文件比较跳过链接、内部状态、依赖和构建目录，复用 Read 审批策略跳过需要审批的敏感内容。直接 Write/Edit 的需审批目标只在原审批通过后核对。报告最多保留 256 项、48KiB，且受会话剩余容量限制。
- “运行期间检测”表示运行前后的工作区变化，也可能来自用户或其他程序；项目外命令效果、未覆盖的子工具和超限内容可能遗漏。覆盖受限时报告会显示说明，不承诺列出所有变化或判定所有文件的作者。
- 编码回退按有界记录处理；同一行混用编码或字节同时符合多种编码时仍可能存在歧义。历史中已经保存为替换字符的文本无法无损恢复，需要重新执行以取得正常输出。
- 0.1.8 的项目概览、媒体预览、附件粘贴和后台作业所有权边界继续保留。Monitor 仍只控制本会话拥有的进程，不按名称或端口批量关闭其他程序。

最终验证结果以 [本轮验收报告](reports/2026-10-17-v0.1.9-verification.md) 为准；源码与正式安装版的区别见 [Hub 使用说明](trailblazer-hub-module.md)。

## 2026-10-18 体验修正

按用户提供的 Codex 示例，将“思考片段”修正为面向用户的公开过程说明，并使用浅色气泡。工具按连续阶段展示，保持“说明 → 操作 → 新说明 → 后续操作 → 最终答复”的顺序；各阶段仍属于同一用户轮次，侧栏保留完整工具链。历史进度不再持续标记生成中，运行指标仅附最终回复，文件清单始终位于本轮末尾，包含停止或失败的情况。追加用户引导时，当前回复继续正确显示生成状态。版本保持 0.1.9，验证记录见 [气泡修正验收](reports/2026-10-18-progress-bubbles-verification.md)。
