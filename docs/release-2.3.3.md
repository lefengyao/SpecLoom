# SpecLoom 2.3.3 更新

修复实体工作台布局偶发保存失败的问题。

## 修复

- 工作台在挂载测量与拖动时会连续发起多次布局保存，每次都是「写临时文件 + rename」到同一个侧车文件；Windows 上并发 rename 同一目标会间歇性 `EPERM`，表现为 `INTERNAL_ERROR · 无法保存实体工作台布局`。
- 主进程按文件路径串行化保存（跨 store 实例共用队列），并对 `EPERM`/`EBUSY`/`EACCES` 做最多 4 次退避重试；创建目录失败也纳入同一错误包装。
- 错误信息现在带底层文件系统错误码（例如「无法保存实体工作台布局（EPERM）」），不再只有一句笼统提示。
- 渲染层合并连续保存：同一时刻只有一个保存在途，期间的多次更新合并为最新一份，失败后仍会继续发送最新布局。

## 验证

- 12 次并发保存全部成功，目录中只剩目标文件，内容为最后一次写入。
- 保存合并：突发 3 次更新只发出 2 次请求（首次 + 最新），中间态被丢弃；首次失败后仍发送最新布局。
- 2.3.2 的布局参数校验修复、2.3.1 的 Git 差异着色与批量暂存、实体工作台尺寸与防重叠、版本冲突修复、组件继承与配图裁剪保持不变。
