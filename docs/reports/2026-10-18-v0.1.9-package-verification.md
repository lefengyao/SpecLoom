## 构建和源码检查

- `npm run typecheck`：通过。
- `npm run test:e2e -- tests/e2e/chat-progress.spec.ts tests/e2e/source-runtime.spec.ts --output=.local/playwright-v019-package`：3/3 通过，43.7 秒。
- `npm run build`：退出 0，生成安装版、便携版、blockmap 和 `win-unpacked`；使用 Electron 41.0.3、electron-builder 26.15.3。Vite 的第三方注释和大 chunk 提示未阻止构建。
- `npm run module:build`：退出 0，模块 ZIP、SHA256 及发布索引已生成。

全量测试首轮 `npm test -- --reporter=dot --maxWorkers=4`：1669 通过、13 跳过、1 失败。失败项为 `tests/core/process-encoding.test.ts` 的 `powershell can relay a legacy native program's GBK bytes`，收到退出码 1 和空输出。随后该编码文件 24/24 通过，相同命令额外 5 次串行和 8 次并行均通过；受控 1 秒超时可以复现相同表象，但首轮缺少超时状态记录，不能据此断言根因。诊断期间未修改源码或放宽测试。

构建与桌面 smoke 均结束后，以相同参数复测全量：1669 通过、13 跳过、1 失败，耗时 406.22 秒。编码用例本次通过；失败转为 `tests/integration/project-core.test.ts` 的 `bounds completed history separately from active task capacity across restarts`，在创建/完成 128 个任务的测试中达到 60000ms 时限。因此本轮不能报告全量测试全部通过。

随后执行 `npx vitest run tests/integration/project-core.test.ts -t 'bounds completed history separately from active task capacity across restarts' --reporter=verbose --maxWorkers=1`，目标用例在原有 60000ms 时限内通过，耗时 49380ms；同文件其他 16 项因名称筛选未执行。两轮全量中的不同失败项均已单独复验通过，但不能将组合结果称为一次全量绿色。全量的 13 项跳过保留在原始日志中，包含 Docker daemon 不可用时跳过的集成测试。
