# SpecLoom 2.5.0 更新

补上锚点的场景校验，并把系统、功能、架构决策做成结构化编辑。

## 场景校验

- 实体规范可声明 `scene: <项目相对路径>.tscn`；详情表单里新增「场景文件」输入，留空即清除。
- 校验读取该 `.tscn` 的节点段，算出相对根节点的路径集合，再逐个核对锚点的 `node`：
  - 场景文件不存在 → `SCENE_NOT_FOUND`
  - 文件里没有任何节点段 → `SCENE_INVALID`
  - 锚点指向的节点在场景里不存在 → `ANCHOR_NODE_MISSING`（诊断落在声明该锚点的文件上）
- 检查范围包含实体自身声明的锚点，以及所有已挂载组件声明的锚点（含 `extends` 继承来的）。
- 未声明 `scene` 的实体不做任何场景检查，不会产生误报。

## 结构化编辑

- **系统**：勾选式编辑引用的组件、引用的实体、依赖的系统。
- **功能**：`status` 下拉（planned / active / done）+ 关联系统勾选。
- **架构决策**：`status` 下拉（proposed / accepted / superseded）+ 影响的系统勾选 + 「取代的决策」下拉。
- 勾选项直接写回 front matter 的字符串 ID 列表，保存仍走统一的资料保存与校验流程。

## 兼容

- 现有实体没有 `scene` 时行为不变；已有系统/功能/决策文档可以继续用源码编辑，也可以改用结构化表单。
- 2.4.1 的挂载编辑与锚点继承、2.4.0 的三类规范保持不变。
