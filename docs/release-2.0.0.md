# SpecLoom 2.0.0 更新

2.0.0 将 SpecLoom 从单一项目工作区扩展为可安装插件的桌面工作台，并内置第一个官方插件：Git 管理。

## 插件系统

- 新增 SpecLoom 插件清单 `plugin.json`，支持主进程模块和独立 HTML 页面。
- 插件可放在内置资源目录或用户数据目录；用户插件默认禁用，官方插件默认启用。
- 插件管理页新增 SpecLoom 插件区，支持启用、禁用、本地安装、卸载、定位目录。
- 插件页面通过独立的 `specloom-plugin://` 协议加载，并使用受限的宿主桥调用命令。
- 插件页面出现在左侧“插件页面”分组；禁用或卸载后入口自动移除。
- 当前采用可信本地插件模型：主进程插件拥有完整 Node 权限，界面会显示信任警告。

## 官方 Git 插件

新增官方插件 `specloom-git`，默认启用。

支持：

- 仓库初始化
- 工作区状态与文件变更
- 单文件 diff
- 暂存 / 取消暂存
- 提交
- 本地分支列表、创建、切换
- fetch
- pull（仅快进）
- push
- 提交历史与单次提交详情

认证使用系统 Git 凭据，SpecLoom 不保存 Git 令牌。

暂不支持 merge/rebase 冲突处理、force push、删除分支、stash、tag、远程管理。

## 聊天与流式性能

- 流式文本和思考只更新内存，不再每个 token 重写完整会话 JSON。
- 每 128 个流事件做一次检查点；工具、审批、上下文、完成、错误和取消边界强制落盘。
- 新增轻量 `SessionDeltaEvent`，主进程向渲染进程推送文本增量；完整快照仍用于边界校正。
- 检查点失败会回滚到最后一次成功保存的状态。
- 最终回复指标新增“总耗时”，按整条回复从开始到结束计算一次。
- 工具事件不再逐次触发完整会话写盘。

## 其他修正

- 修复 MiMo `tool_calls: null` 和文本数组导致的 malformed response。
- 外部编辑器改为可选；未配置时打开项目文件夹。
- 中英文界面继续保留，语言设置随本机偏好保存。
- 修复插件启用开关被全局按钮样式撑成圆形的问题。
- 补齐插件 IPC 操作白名单，修复 `Unknown desktop operation`。

- Windows x64 安装版与便携版由 `npm run build` 生成。
- 内置插件作为 `resources/plugins` 额外资源打包。
- 安装包未签名，Windows 可能显示 SmartScreen 提示。
