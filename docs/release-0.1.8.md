# SpecLoom 0.1.8 源码更新

本轮根据 2026-10-17 的七项体验反馈更新源码。安装版和 Hub 已安装模块尚未替换；本轮未生成安装包、发布 ZIP 或模块包。

## 使用变化

1. 所有近期项目都有“从列表移除”入口，包括仍然存在的项目。移除仅清理近期记录，项目文件保留，再次打开后会重新进入列表。
2. “关于项目”展示 Git 可用性、仓库位置、当前分支或 detached HEAD、本地及远程跟踪分支、fetch/push 地址、README 和 `.gitignore`，并显示 SpecLoom 版本等信息。智能体发送前取得同一来源的真实项目概览，可建议初始化、补充忽略规则和 README，协助分支与推送操作。Git 写操作沿用现有审批；查看页面不会自动初始化或联网。
3. 项目树和资源列表可打开普通项目图片、音频、视频。图片支持缩放和适应视图，音视频使用原生播放、进度和音量控件，视频可放大或全屏。普通文本以只读方式打开；资料编辑继续使用原流程。
4. 项目文件区域增加“隐藏 import 文件”复选框，默认显示，按项目记忆；大小写不同的 `.import` 也会一起过滤，不修改磁盘文件。
5. 减少会话头和输入区占用，单行输入框从 44px 起随内容增长，最高 160px。相同窗口下，聊天阅读区在 1366×768 从 375px 增至 489px，在 1920×1080 从 687px 增至 801px。
6. 图片和文档可以通过选择文件、键盘或右键粘贴加入聊天，显示处理状态、移除入口和可展开的提取正文。图片实际进入模型视觉载荷，TXT/PDF/DOCX 的正文进入发送和引导消息。异步粘贴、切会话、新建失败重试、部分附件失败及发送失败均保留对应草稿和附件归属。
7. Monitor 支持增量读取、相同作业复用、停止及按原命令重启。Windows 子进程以 Job Object 管理，避免 shell 退出后留下持有输出管道的孤儿进程。停止会话不再无限等待失去响应的工具；旧初始化、问题或完成回调不能覆盖停止结果或新一轮运行。连续无进展会显示提示并建议延长等待，同一运行作业至少持续 120 秒且重复五次无变化才结束重复轮询；进展、作业切换和其他工作会重置预算。

## 范围与限制

- 媒体解码由 Electron/Chromium 支持情况决定，不提供转码；有效 PNG、WAV、WebM 已用源码窗口验证。普通图片上限 32MiB，音视频走本地流与 Range 请求。
- 附件最多 16 个、原始数据合计 16MiB；单张图片 2MiB，单份文档 6MiB，提取正文 64KiB。PDF 最多处理前 20 页，没有 OCR；加密、损坏、扫描件无正文和旧 `.doc` 会显示具体原因。
- PDF/DOCX 使用可终止 Worker，最多两个同时解析，单次最长 10 秒。附件不自动写入项目或全局离线资料库；图片继续使用现有会话载荷，未新增历史图片持久化格式。
- Windows 原生文件粘贴回退只承诺一个本地普通文件，支持 `FileNameW` 及 Electron 规范化后的 `text/uri-list` 文件表示；多文件通过 DOM FileList 或选择器。不会把普通文字中看起来像路径的内容当作文件读取，文件表示无效时不会悄悄改添预览位图。
- Monitor 只控制本会话启动和拥有的进程。检测到外部实例或端口占用时会明确报告，不能仅按名称或端口结束其他程序。停止等待有边界，未确认结束时不会声称已关闭或开始重启。
- 独立源码窗口与 Hub 模块源码窗口分别验收；正式安装版和正式 Hub 发布包仍需用户明确要求后再打包验证。

验证明细见 [本轮验收报告](reports/2026-10-17-v0.1.8-verification.md)。
