# StoryFabric 提示词与工作区对齐设计

## 目标

让 SpecLoom 的系统提示词、全局用户个性化提示词和项目工作区提示词形成稳定的三层注入链路，并让普通对话与任务智能体使用同一套提示词上下文，同时保持普通对话无项目工具权限、任务仍需用户显式创建和授权。

## 设计

### 三层提示词

运行时始终按以下顺序拼接：

1. 内置系统提示词：代码维护，负责 Godot 工具、安全、范围、版本、审批和验证规则。
2. 全局用户提示词：现有 Preferences.customInstructions，跨项目生效。
3. 项目工作区提示词：当前项目的 specs/prompts/system-prompt.md，仅当前项目生效。

最后追加任务作用域说明或普通对话说明。用户提示词不能扩大 TaskScope、绕过审批、改变工具白名单或修改凭据处理。

### 项目提示词存储

- 新增 ProjectCore 的读取和保存能力，路径固定为 specs/prompts/system-prompt.md。
- 项目初始化时创建 specs/prompts 目录，但不覆盖已有文件。
- 读取不存在的文件返回空字符串。
- 保存使用现有安全文件策略和原子写入，限制大小为 16,000 字符。
- 通过专用 IPC 暴露 readWorkspacePrompt 和 saveWorkspacePrompt，设置页保存不创建任务。

### 运行时注入

- ProjectCore 在每次任务运行和普通聊天运行前读取当前项目提示词，编辑后下一次运行立即生效。
- 有项目时普通聊天注入内置、全局和项目三层；无项目时只注入内置和全局。
- 普通聊天仍使用无工具 catalog，任务聊天仍使用当前任务 scope 和工具 catalog。

### 设置界面

在现有设置的智能体区域分成两个编辑区：全局个性化提示词和当前项目提示词。未打开项目时项目编辑器禁用；打开项目后读取当前文件。保存失败保留草稿，不清空输入。

### 测试

- 核心测试验证项目提示词读写、路径限制、原子保存、16,000 字符限制和不存在文件行为。
- 集成测试验证三层提示词顺序、任务与普通聊天都注入项目提示词、无项目普通聊天不读取项目文件。
- 渲染测试验证项目提示词加载、保存状态、失败保留草稿和无项目禁用。
- 现有全量测试、类型检查、Lint、E2E 和 build:app 继续通过。

## 不纳入本阶段

不引入 StoryFabric 小说专用工具、记忆系统、编排阶段、子智能体和多会话持久化工作台；不自动把普通消息转换成任务；不修改供应商、模型、凭据或现有任务历史格式。

## 实现与验收（2026-10-05）

- 已接入统一提示词组装器，任务与普通对话每次运行都读取当前项目文件；未打开项目的对话仅注入内置与全局要求。
- 已实现专用 `readWorkspacePrompt` / `saveWorkspacePrompt` IPC，请求绑定项目身份，保存携带文件版本，拒绝过期项目请求与外部编辑冲突。
- 首次保存使用同步临时文件与独占硬链接原子发布；更新复用安全路径、原子替换及失败清理。读取和保存均限制为 16,000 字符。
- 设置页提供独立项目编辑区、加载与保存状态、失败草稿保留及重新加载；未打开项目时禁用，切换项目忽略旧的加载与保存结果。
- 验证通过：全量回归 410 项通过、10 项 Docker 相关测试跳过；TypeScript 类型检查、ESLint、`build:app` 和桌面 E2E 1/1 通过。E2E 实际保存提示词，并核对任务与普通对话的请求注入顺序。
