# SpecLoom Hub 多窗口

用户要求 SpecLoom 像 StoryFabric 一样支持多开。继续使用 Hub 0.1.6 API 2；每次启动创建窗口，模块升级到 0.1.4。

每个窗口独立选择项目。模块内按数据目录共享全局设置、供应商和全局资料服务；按规范化项目路径共享 DesktopController、项目状态、SessionRuns 和 MCP 服务。同一会话只运行一次，其他窗口可查看进度、引导、审批和停止。不同项目分别运行。最后一个查看项目的窗口关闭后才关闭该项目的后台和 MCP。

窗口仅释放自己的订阅和项目引用。关闭或初始化失败须清理已取得的引用；关闭期间禁止新 IPC，已开始的操作先得到取消或完成，再退出。项目切换不能遗留无主后台；最后一个窗口有工作时沿用等待操作结束的限制。

不采用直接修改清单的方案，因为独立缓存会丢失并发设置和会话；不采用每窗口独立用户配置目录，因为模型、资料和历史会分裂。按项目共享服务保留现有工作区逻辑并避免在 Hub 增加 SpecLoom 特有行为。

验证覆盖并发启动、不同项目、同项目运行可见性、重复发送拒绝、跨窗口引导、关闭单窗口不影响其他窗口、最后窗口关闭清理、失败初始化、全局配置并发写入与 UI 通知、卸载更新限制。实际 Hub 0.1.6 发行包用于验证兼容性。
