# SpecLoom 项目资料层级浏览与关系图改版

状态：用户已确认“清晰台账”方向；本规格待审。

## 背景

实体、组件、设定、地图、UI 和规范资料共用 `MaterialExplorer`。当前浏览区按名称平铺卡片或列表，资料的 `parent` 只在编辑详情中设置，浏览时难以看出父子关系。实体类型不能在结果中快速检索，组件的官方 / 自定义身份也需要更直观地呈现。资料分组已有独立的层级树，必须和资料之间的真实父级关系分开显示。

当前数据摘要包含 `parent`、`extends`、组件绑定、类型、分组路径和组件来源。`materialTree` 已能从 `parent` 建立树并将错误关系、无法解析的资料留在单独节点下。改版应复用这些数据，不改资料模型或项目文件。

## 目标

- 为实体、组件、设定、地图、UI、规范提供统一且清楚的资料浏览工作台。
- 默认以层级列表浏览；新增横向关系图，让真实资料父子关系一眼可见。
- 保留现有图标卡片视图，三个视图使用同一搜索、筛选、选择和资料集合。
- 让资料分组、资料父级、实体继承和组件组合的含义互不混淆。
- 改善实体类型检索和组件官方 / 自定义来源辨识。
- 视图切换和本地筛选只改变展示，不触发目录或资料重新读取，也不丢失当前选择。
- 在详情中把资料父级、实体继承、分组与组件绑定清楚分区，减少编辑时混淆。

## 范围

改版覆盖“实体、组件、设定、地图、UI、规范”六类项目资料页面、共用浏览器和详情中的关系区。应用侧栏、聊天、设置、插件、通用项目文件浏览器不在本轮范围。详情的保存、版本冲突、源码编辑、组件字段和引用校验行为保持不变；只调整关系字段的视觉分区与说明。

## 已确认的视觉方向

采用“清晰台账”作为默认方向：现有 PC 应用外壳和项目导航保持一致；内容区顶部提供类别标题、搜索、类别筛选和视图切换；左侧常驻当前类别的分组树，右侧为资料内容。列表优先，关系图通过同一工具栏切换。使用现有主题变量和青绿色强调色，强化标题、列名、层级缩进与选择状态，减少重复边框和空卡片感。窄窗口可收起分组栏；关系图在内容区内平移，不扩大整个应用页面。

“图谱工作台”仅作为可比较的备选方向，不作为实施方向。

## 页面结构与模式

```text
项目资料 / 实体
┌──────────────────────────────────────────────────────────────────────┐
│ 搜索名称、说明、ID 或路径    [实体类型]    [卡片] [列表] [关系图]    │
├──────────────────┬─────────────────────────────────────────────────┤
│ 分组树           │ 分组路径 / 当前筛选                      新建资料 │
│ 全部资料         │ 名称与说明       类型/来源      父级      所属分组 │
│ 未分组           │ ▸ 巡逻兵         敌人          根实体    基础实体 │
│ 基础实体         │   ├ 近战巡逻兵   敌人          巡逻兵    基础实体 │
│   ├ 角色         │   ├ 远程巡逻兵   敌人          巡逻兵    基础实体 │
│   └ 敌人         │   └ 精英巡逻兵   敌人          巡逻兵    基础实体 │
│ 关卡资源         │                                                 │
└──────────────────┴─────────────────────────────────────────────────┘
```

- **层级列表（默认）**：以缩进、展开控件和细连接线展示 `parent`。每行显示名称、说明摘要、实体类型或组件来源、直接父级和分组路径；没有父级的项标为“根资料”。折叠仅影响列表呈现，不改变筛选结果或关系。
- **关系图**：以左到右的列显示真实资料父级关系。根资料位于第一列，后代逐层向右；节点显示名称、类型或来源和子项数量。每条连线只代表 `parent`。可选中节点查看其详情入口，可折叠分支；画布提供适配视图和缩放、平移操作，滚动限制在画布内部。
- **卡片**：保留当前图标 / 图片卡片视图与已有图片预览。该模式按匹配结果展示资料，不承诺展示父子连线；用户可切换到列表或关系图查看结构。
- 三种模式使用同一份已加载资料目录和当前筛选状态。切换模式保留选中资料、搜索文字、筛选条件、分组树展开状态；不重新读取文件。
- 选中列表行或关系图节点继续调用现有资料选择流程，在现有编辑区打开对应资料。关系图中切换节点也更新当前资料选择。
- 详情编辑中的“资料父级”继续写入 `parent`；实体的“继承自”单独写入 `extends`，并分别显示短说明。分组选择仍独立呈现；实体组件组合仍位于组件区。样式可以统一整理，但字段及保存行为不变。

## 关系语义

- 左侧分组树是归档和筛选；关系图与层级列表中的父子边只来自资料字段 `parent`。分组不得作为关系图的隐式根节点，也不得显示为资料父级。
- `extends` 是实体原型继承；组件绑定是组合；两者在节点详情或资料详情中分别标注，不画成 `parent` 的同一种边。
- 关系图仅连接同一资料类别中可解析且无循环的 `parent` 目标。缺少目标或存在循环的项目继续进入“关系错误”区域并提供源码修复入口，不绘制错误连线、不静默丢弃资料。
- 无效或无法解析 front matter 的资料仍能从“未归类”状态进入源码修复；不得因图表无法表达而隐藏。

## 搜索、分组与类别筛选

- 关键词继续匹配名称、说明、ID、文件路径和完整分组路径。
- 实体页使用已有受控类型：通用实体、角色、敌人、物品、系统、事件。地图仍是独立类别，不作为实体类型。
- 组件页使用官方 / 自定义来源筛选，复用现有 `componentScope` 判定；来源徽标在卡片、列表行和图节点中一致显示。
- 组件来源作为标签和筛选条件，不作为资料树节点或第二种连线；全部组件视图保持 `parent` 树连续。筛选来源后，必要的异来源父组件可按“路径上下文”显示。
- 设定、地图、UI、规范页不新增未定义的类型筛选。
- 关键词、类别筛选和分组筛选取交集。选中父分组仍包含全部后代组；“全部资料”和“未分组”保持可用。
- 为保留关系上下文，如果筛选命中某资料但其 `parent` 未命中其他条件，层级列表和关系图可把该祖先作为弱化的“路径上下文”节点显示；上下文节点不计入命中数。卡片只展示命中资料。
- 结果标题展示当前分组路径和命中数；当有额外筛选时同时显示总资料数。无匹配、空分组、未分组为空分别使用不同说明，并提供清除搜索/类型筛选或创建子分组的入口。
- 组件来源筛选若隐藏某个被筛选资料引用的父组件，关系图仍可显示父组件作为弱化上下文节点；该节点不计入当前来源筛选命中数。

## 视图偏好与响应式行为

- 扩展当前 `specloom.materials.view` 偏好以支持 `icons`、`list`、`graph`。新用户或不存在有效偏好时默认 `list`；已有 `icons` / `list` 偏好继续生效。
- PC 桌面保留左侧应用导航，在资料浏览器内部使用独立分组栏和主内容区。中等宽度下分组栏可折叠；较窄窗口默认收起，搜索筛选控件换行但保持可操作。
- 关系图只在画布容器内横向/纵向滚动或缩放，列表在结果区内滚动，窗口本身不出现横向溢出。
- 默认折叠较深的非选中分支；选中资料所在路径自动展开。数据计算采用已加载目录派生，避免切换视图触发 IPC。

## 不在范围内

- 不改变 `parent`、`extends`、`components`、`relations` 的存储和验证规则。
- 不移动或重命名项目资料文件，不改变项目分组清单及 `groupId` 迁移。
- 不重做聊天、应用导航外壳或详情编辑表单，不改变保存和版本冲突流程。
- 不新增外部图表依赖；关系图只需要表达层级节点和边。

## 验收标准

1. 六类资料页使用相同的分组树、搜索栏和卡片 / 层级列表 / 关系图切换，列表为新默认视图。
2. 列表通过缩进、折叠和父级列清楚显示多级 `parent`；选择父项、子项能打开对应资料详情。
3. 关系图根节点和后代节点按 `parent` 层级从左向右排列，连接线不把分组、继承或组件组合误画成父级关系。
4. 实体按现有实体类型筛选；组件按官方 / 自定义来源筛选；关键词、类别筛选、分组筛选可以组合，三个视图结果一致。
5. 父组选择包括后代分组；关系上下文节点与实际命中计数有清楚区别；卡片模式只显示命中资料。
6. 缺失父级、循环父级和未解析资料有明确的错误/修复入口，在任何模式下都能找到。
7. 切换视图不会发起资料读取 IPC，不丢失选中资料和筛选状态；无效的存储偏好安全回落到层级列表。
8. 窄窗口可折叠分组栏，图表在局部画布内滚动或缩放，页面没有横向溢出。
9. 详情关系区清楚区分资料父级 `parent`、实体继承 `extends` 和分组；编辑后仍使用现有保存与关系校验。

## 实施前自审

- 保留了既有图标卡片模式，避免移除已支持的浏览方式。
- 规格显式区分左侧归档分组与资料 `parent`，并单独保护实体继承和组件组合语义。
- 所有类别筛选复用已有字段，没有为设定、地图、UI、规范虚构类型。
- 选择和资料编辑沿用现有流程，避免把 UI 改版扩大到保存或项目数据迁移。
- 实施时需重点检查按搜索或来源筛选后保留祖先上下文的计数、选择和可访问性。
