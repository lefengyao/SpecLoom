# SpecLoom 资料分类与浏览体验设计

状态：用户已确认，实施中

## 背景

项目资料浏览器目前在各分类页共用一个平铺列表。每条资料只有一个自由文本 `group`，工具栏提供平铺分组下拉框；实体类型只在详情表单里编辑，列表没有对应筛选。这样既无法维护父组和子组，也难以在资料多时缩小范围。组件页已有“官方组件 / 自定义组件”来源身份，应继续与用户定义的分组分开表达。

资料的 `parent` 和 `extends` 表示资料之间的引用关系。它们不代表归档分组，不能用来代替文件夹树。

## 目标

- 在实体、组件、设定、地图、UI、规范资料页提供一致、可浏览的层级分组体验。
- 允许先建空分组，再维护子分组；能够重命名、移动分组和资料。
- 在实体列表直接按实体类型筛选，并能与关键词、分组筛选组合。
- 保留项目已有资源路径、父级资料引用、组件来源身份，以及网格/列表切换。
- 将已有平面分组平滑迁移为层级树的根节点。

## 不在范围内

- 不把分组写入实体文件的目录层级，不移动 Markdown 资料文件。
- 不改变 `parent`、`extends` 的关系语义。
- 不为目前没有稳定子类型字段的设定、地图、UI、规范页凭空增加类型体系。
- 不改变组件“官方 / 自定义”的来源判定规则。

## 已确认的方案

1. 使用左侧常驻分组树，右侧显示当前筛选结果；搜索框、类别筛选、视图切换位于内容区顶部。
2. 每个资料类别各自拥有一棵分组树。各页布局和管理方式一致，但允许不同类别使用各自的分类名称。
3. 分组树是项目中的独立分类数据，可包含没有资料的空节点。资料通过分组标识关联到节点，而非依赖资料之间的父子引用。
4. 选择父分组会包含它的所有后代资料；左侧计数也包含后代。未分组是虚拟入口，不作为可重命名的普通分组。
5. 删组只允许删除没有资料且没有子组的空节点，不级联删除资料。
6. 继续保留现有网格 / 列表切换。

## 备选方案和取舍

- **项目级分组清单，每类独立成树（采用）**：支持空组，重命名或移动组不会更改资源路径；资料可通过稳定标识归组。旧分组可导入为根节点。
- **全项目共用一棵树**：实现统一，但角色、组件、地图等类别容易共享不相关的分类名称和层级。
- **从每条资料的路径文本推导分组**：改动较小，但空分组无法存在，移动和重命名也需要改写多条资料。
- **用文件系统目录表达分组**：与实体、地图等既有目录约定冲突，也会更改资料路径和引用。

## 页面结构

```text
项目资料类别
┌──────────────────────────────────────────────────────────────┐
│ 搜索名称、说明或分组路径   [实体类型筛选]   [网格] [列表]    │
├────────────────┬─────────────────────────────────────────────┤
│ 分组           │ 当前分组路径 / 当前筛选                      │
│ 全部资料       │ 资料卡片或列表行                             │
│ 未分组         │ 名称、说明、所属分组路径、类别特有标记         │
│ 基础实体       │                                             │
│ ├─ 角色        │                                             │
│ ├─ 敌人        │                                             │
│ └─ 道具        │                                             │
│ 前院           │                                             │
│ └─ 可交互物    │                                             │
│ [新建分组]     │                                             │
└────────────────┴─────────────────────────────────────────────┘
```

桌面布局以约 240 px 的分组栏和可伸缩的资料区为基准，窄窗口时允许分组栏收起。树节点显示名称和资料数量；非空分组可以展开/收起。选择节点后，内容区展示路径面包屑。列表卡片显示完整分组路径，避免相同子组名造成误认。

## 搜索与筛选

- 关键词匹配名称、说明、ID、文件路径和完整分组路径。
- 实体页提供单选的“实体类型”筛选，选项使用实体详情现有枚举：通用实体、角色、敌人、物品、系统、事件。地图资料属于地图类别，不重复混入实体类型筛选。
- 组件页提供官方 / 自定义来源筛选；它与分组筛选相互独立。
- 设定、地图、UI、规范页提供同样的关键词和分组浏览。只有某类别将来存在受控类型字段时，才显示对应的类型筛选。
- 关键词、类型、分组采用交集过滤；筛选条件变化不重置分组树的展开状态。
- “全部资料”和“未分组”始终可见。无匹配结果和空分组使用不同的空状态，并保留清除筛选或新建子组入口。

## 分组管理

- 分组树工具栏提供新建根分组；每个节点菜单提供新建子分组、重命名、移动、删除。
- 组名不能为空，同级不允许重名；组节点使用稳定 ID，显示名称可以更改。
- 移动分组会带动整个子树，原有资料关联保持不变。禁止把组移动到自己的后代之下。
- 删除仅允许空叶节点；含资料或子组时说明需先移动内容。
- 资料详情的“分组”字段改为层级选择器，可选未分组或当前类别任意节点；保存后列表、分组计数和搜索立即同步。
- 不要求拖拽。移动操作通过明确的分组选择菜单完成，避免把资料文件路径变化和视觉归档混为一谈。

## 项目数据与迁移

- 项目保存一份可随项目复制和版本管理的分组清单。按类别保存组节点的稳定 ID、名称、父组 ID 和排序位置。
- 资料保存可选的 `groupId`；摘要层将 ID 解析为完整分组路径，供 UI、检索和工具结果复用。无分组的资料不写入普通组 ID。
- 老资料的字符串 `group` 按“类别 + 现有名称”去重，创建为该类别的根分组，并将资料关联到对应稳定 ID。文件路径及 `parent` / `extends` 不变。
- 迁移必须幂等且保留无法解析的原始值；发生版本冲突时不覆盖用户编辑，并给出可恢复的错误状态。
- 旧工具仍以可读分组名称/路径查询摘要；新树结构应能返回分组路径和空组信息，避免工具侧退回平面分类。

## 验收标准

1. 能在任一资料类别创建根组、空子组，重命名和移动组；删除非空节点会被阻止且不会移除资料。
2. 选择父组会包含全部后代资料；选择子组只包含该节点及其后代；未分组筛选独立可用。
3. 实体可以按类型检索，并可同时叠加关键词和分组筛选；过滤结果与当前显示模式一致。
4. 每个资料类别共享同一浏览交互；组件仍能清晰显示和筛选官方 / 自定义来源。
5. 详情编辑分组后，组计数、路径标签、搜索和工具摘要一致更新。
6. 打开旧项目后，原有平面分组可见为根组；升级过程不重命名或移动资源文件，也不改变父级关系。
7. 搜索无结果、空分组、未分组和组删除受阻都有明确说明及下一步入口。
