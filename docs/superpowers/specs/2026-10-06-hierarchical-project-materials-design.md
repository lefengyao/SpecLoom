# 分层项目资料与组件设计

## 目标

让项目资料支持逐层分类、实体原型继承和组件组合。开发者可以先创建“物品”“武器”等大类，再创建具体实体；实体创建只填名称，详细说明和组件在创建后补充。组件由独立页面管理，生命值、坐标、速度等字段定义可供多个实体复用。

## 关系与文件

| 关系 | 数据字段 | 含义 |
| --- | --- | --- |
| 资料父级 | `parent` | 同类资料的实际父级 ID 或路径，用于资料树层级。 |
| 实体继承 | `extends` | 单个实体原型引用，供继承组件和后续生成读取。 |
| 组件组合 | `components` | 组件引用及当前实体的 `values` 覆盖值。 |
| 普通关联 | `relations` | 不承担分类、继承或组件语义的实体关联。 |

分类节点和实体使用相同的资料模型。分类必须有真实文件，子项由父级引用反向索引，文件中不维护 `children`。父级与继承分别检查循环关系。实体、组件、设定、地图、UI 页都可显示资料层级；父级选择限定当前资料类别。

```text
specs/
  entities/<id>.md
  components/<id>.md
  settings/<id>.md
  maps/<id>.md
  ui/<id>.md
```

实体文件也可放在 `specs/entities/` 的嵌套目录，文件名始终与 `id` 一致；资料分类由 `parent` 决定。实体 ID 自动使用安全英文名称或类别前缀，加 UUID 短后缀；编辑名称、类型和关系时 ID 与路径保持稳定。

## 创建与编辑

1. 实体页点击“新建实体”，只填写名称。选中已提交的实体后，“新建子实体”自动带入该实体为父级。
2. 新实体立即成为当前页面草稿，在详情中填写说明、实体类型、父级、继承和 Markdown 正文。
3. 组件页选择空白、生命值、坐标或速度模板，填写名称后编辑字段。生命值模板包含 `current` 与 `max`，默认均为 100；坐标包含 `x` 与 `y`，默认均为 0；速度包含 `value`，默认 180。
4. 完善并提交组件及父级资料后，在实体详情选择组件并添加，随后编辑该实体的字段值。
5. “暂存编辑”进入限定单文件范围的差异审查，批准后写入项目。结构化详情与“源码编辑”操作同一份 Markdown/YAML。

App 持有当前项目的资料草稿，切换资料页或工作区后仍可继续编辑；有未暂存修改时保护窗口退出，切换项目需确认丢弃修改。尚未暂存的页面草稿不持久化到磁盘；已暂存内容使用现有审查任务持久化机制。组件与父级引用指向真实项目文件，新的依赖应先提交。

有未暂存修改的资料遇到版本冲突时，“重新读取”先确认丢弃当前资料的修改，再读取最新文件版本；其他资料草稿保留。重新读取后使用最新版本继续暂存。

## 组件契约

`specs/components/health.md`：

```yaml
schemaVersion: 1
id: health
type: component
title: 生命值
description: 当前值与生命值上限。
fields:
  - key: current
    label: 当前值
    type: number
    default: 100
  - key: max
    label: 上限
    type: number
    default: 100
```

字段类型为 `number`、`string` 或 `boolean`，默认值必须匹配类型，数值必须有限。字段名称使用字母或下划线开头、后续字母/数字/下划线的形式，不能重名或使用 `__proto__`、`prototype`、`constructor`。

实体实例：

```yaml
schemaVersion: 1
id: fire_goblin
type: entity
title: 火焰哥布林
description: 近战敌人。
status: draft
version: 1
parent: enemies
extends: goblin
components:
  - id: health
    values:
      current: 80
      max: 80
relations: []
source: developer
```

组件可用 ID 字符串或引用对象挂载；对象的 `values` 只能覆盖定义中已有字段，值的类型必须匹配。省略覆盖值时使用继承实例值，再回退到组件默认值。继承链按基实体到派生实体逐层覆盖，当前实体的显式值优先；继承的组件在详情中显示来源，并提供“覆盖继承组件”。同一实体不能重复挂载同一个组件。

组件定义独立于实体实例。改变默认值不改写实体已保存的显式值；新增字段使用定义默认值。在详情编辑中，已被实体挂载的组件原有字段禁止直接改名、改类型或删除，需先处理引用者；显示名称、默认值和新增字段仍可编辑。字段与组件描述是生成输入，游戏运行时代码由引擎工作流实现。

## 实现与校验

`project-materials` 解析 YAML front matter，拒绝重复键并限制别名展开，保留未知数据字段及完整 Markdown 正文。`materials-model` 构建临时目录、关系树与循环判断。`DocumentsView` 读取文件及维护当前选择与草稿，`MaterialDetails` 提供结构化编辑。

校验覆盖真实父级与类别、单个继承目标、缺失目标、版本引用、父级/继承循环、组件目标类别、重复挂载、字段重名、未知覆盖字段、数值有效性及类型一致性。缺失或循环的父级关系显示在“关系错误”，无法解析的资料保留在“未归类”，均保留源码修复入口。类型化显示工具过滤无效字段或引用时不修改源数据，验证仍检查原始 front matter。

资料读取完成前禁用结构化编辑；引用者读取失败时保留源码修复和刷新入口。详情表单阻止字段重名和保留键。源码编辑沿用人工审查语义，可保存开发中的资料；完整关系与字段校验通过审查页“验证”执行，人工批准本身不代表验证通过。

关系索引为派生视图，不替代文件事实来源。后续引擎生成必须读取当前版本的实体、原型与组件，不能把资料树层级自动当作继承关系。
