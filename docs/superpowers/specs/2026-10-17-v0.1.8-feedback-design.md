## 3. 方案选择

采用“补齐专用只读服务，复用现有智能体权限、原生媒体控件与模型输入”的方案。这样可以让项目页与模型使用同一真实信息，并分别验证文件传输、播放和界面行为。

另外两条路线不作为本版方案：纯 Renderer 修补无法打通普通文件和大视频读取；完整 Git GUI、转码系统和永久附件仓库会扩大这六条反馈之外的范围。Git 分支和推送继续由用户向智能体提出。

## 4. 项目概览与 Git

### 4.1 数据与展示

新增 `projectOverview.read(projectPath)`，不修改静态 ProjectMetadata 的含义，不在 state() 中运行 Git。结果独立提供：

- Git 未安装、非仓库、普通仓库、linked worktree、上级仓库、bare 不支持、检测失败。
- 当前分支/尚无提交/游离 HEAD；本地分支和远程跟踪分支清单，远程符号别名如 origin/HEAD 不冒充独立分支。读取失败与确无分支区分。
- remote 名称、已脱敏 fetch/push 地址；没有 remote 与 remote 查询失败区分。
- 根目录 `.gitignore` 与常见 README 文件的存在、可读、大小信息。
- 检测时间及可恢复的错误提示。

About 拆为独立 `AboutView.tsx`，展示项目信息、Git、README/ignore、SpecLoom 信息。文档使用项目文件只读文本接口，支持展开和打开项目文件页。没有文档时显示缺失并可向智能体提出编写需求，不暗示内容已经生成。

SpecLoom 信息使用真实名称、package 版本、产品介绍与作者 Trailblazer；未核实的官网、许可证、仓库链接不编造。

### 4.2 查询边界

使用 git 可执行文件和固定参数数组、shell:false、单命令 5 秒/总查询 10 秒、输出总量 2 MiB。查询命令只涉及 rev-parse、symbolic-ref、for-each-ref 和 remote 配置读取；不联网、不初始化、不写 safe.directory。清除继承的 GIT_DIR/GIT_WORK_TREE/GIT_CONFIG_COUNT 等覆盖，禁用交互与可选锁。

Git URL 在主进程返回前清除 HTTP(S) userinfo/query/fragment；SSH/SCP 地址安全作文本显示。原始 URL 和 stderr 不进入 IPC、模型上下文或日志。分支列表超限明确说明未完整展示，不能静默当成完整清单。

项目路径由当前 core 校验和固定，不能接受任意仓库路径或命令。About 激活、手动刷新、窗口重新聚焦时查询；项目切换清空旧结果并丢弃迟到响应。Git 失败不阻断 README/ignore 或应用信息。

### 4.3 智能体帮助

从同一服务注入有界、脱敏的真实项目事实。新会话首次实际用户消息在确认非仓库时提示是否需要初始化；没有用户消息不请求模型。后续普通轮次不重复初始化提示，用户主动询问 Git 时再检查。

初始化、编辑 ignore/README、建分支和推送复用 Read/Write/Edit/Bash 与现有审批模式。完全访问模式沿用现有语义；受限模式的 shell 操作仍需现有审批。检测到上级仓库时说明操作范围，缺远程地址时由用户提供，不擅自创建远程仓库。ignore 根据已有规则与引擎合并，保留 specs、项目资产和用户维护的 Skills。

提示词统一接入主聊天、兼容聊天和旧审查任务入口；注入事实不扩大旧任务权限。只更新内置 Skill 不足以覆盖旧项目，因此 Skill 为辅助流程，运行时接入为主体。

## 5. 项目文件与媒体

### 5.1 选择与文本读取

将选中资源与可编辑 Markdown 分开。树和资源列表使用统一选择入口：资料仍走原版本保护的编辑 API；普通 UTF-8 文本通过新只读接口读取；媒体走媒体接口。根 README/ignore 使用同一只读文本能力。

保留 `projectTree()` 的廉价路径枚举；不要通过扩展 documents() 或全项目 listFiles() 为所有媒体计算摘要。文本只在选中时由同一 fd 有界读取、解码并计算版本，最大 1 MiB；不能先 listVersion 无界计算超大文件摘要再拒绝。媒体只在选中时安全打开和读取有界文件头。

### 5.2 媒体传输

采用项目绑定的 127.0.0.1 随机端口媒体服务，可信 IPC 颁发单文件临时不透明 URL。standalone 与 Hub 共用实现；不扩大 Hub context API。

Hub 在 app ready 后加载模块，窗口共享默认 Electron session；因此不能在每个模块窗口独立注册相同 privileged scheme。现有 MCP 也不能供原生媒体使用，因为它只收 POST 并要求自定义 Authorization。

媒体服务支持 GET、HEAD、单 Range、206、416、Accept-Ranges，以及开放区间/尾部范围。多 Range 明确返回 416。本地 token 至少 32 随机字节，只绑定一个文件和一个窗口 owner；Host 精确校验，不开放任意 CORS，不提供目录或路径参数。URL 不持久化、不进入日志。

路径复用 PathPolicy，拒绝越界、绝对/UNC/ADS、链接/junction、保留运行目录。使用已打开 fd、流式读取和背压，大视频不整文件载入内存。每次请求确认授权和文件 generation；替换或删除后停止旧流并提示刷新。每个 owner 最大 4 个有效 lease、服务最大 8 个活动流；申请新选中资源后及时释放旧 lease。

### 5.3 预览与生命周期

- 图片：PNG/JPEG/WebP/GIF/BMP/SVG，普通图片限 32 MiB；适应窗口、100%、缩放和可滚动查看。SVG 只用 img，不以内联 HTML/object/iframe 执行。
- 音频：识别 WAV/OGG/MP3/FLAC/AAC/M4A；原生 controls 提供播放、暂停、音量和拖动进度。
- 视频：识别 MP4/WebM/OGV/MOV；原生 controls 与放大/全屏。是否能解码由 Electron 实际能力决定，失败明确说明，不承诺所有编码或自动转码。
- 不自动播放；加载、不可读、格式不支持、解码失败均有可见状态。

快速 A→B 选择以请求序号避免串图，迟到 lease 必须释放。文件/项目切换、页面隐藏、卸载时暂停、移除 src、load 并释放。NavigationPage 会保留挂载，因此不能只等卸载清理。

owner 来自可信窗口而非 Renderer 参数。窗口关闭/崩溃/非可信导航撤销其授权；Hub 一个窗口切换项目不影响同项目其他窗口。最后后端退出关闭服务、取消流，不让播放阻塞退出。媒体 HTTP 本身不能再次验证 webContents，授权依赖可信发证、不可猜 URL 和主动撤销。

## 6. import 显示选择

在项目文件区域提供“隐藏 .import 文件”复选框，默认不勾选，按后端提供的规范项目路径在本机记忆。仅按文件名后缀、不区分大小写过滤文件；文件夹名或正文含 import 不受影响。

同时处理项目树 entries 和 documents 补入的数据，避免过滤后重新回填；保留 Godot 的既有 uid 规则。存储不可用时本次选择仍生效。选中项隐藏后关闭其只读预览；若未来存在未保存编辑，先沿用草稿保护。该选项只影响显示，文件与智能体读取范围保持现有语义。

## 7. 聊天垂直空间

会话 composer 独立拥有样式，通用 composer 规则排除 session-composer，消除加载顺序冲突。textarea 从 rows=3 改为 rows=1，避免 scrollHeight 仍按三行起算。空/短输入目标 44px，自动增长上限 160px，CSS 与测量逻辑共用变量；创建中草稿、会话切换和容器宽度变化触发重算。

会话标题为紧凑单行，长标题省略并保留完整 title；项目栏与会话头减少垂直留白。桌面工具栏紧凑，窄屏仍能访问所有选项和发送按钮，正文字号维持可读性。

真实窗口验收条件：100% 页面缩放、固定侧栏状态、长聊天、空/短输入、无引导队列与附件；1366×768 消息区不少于 460 CSS px，1920×1080 不少于 760 CSS px，输入区含工具栏不超过 120px。同一条件修改前后目标净增加至少 50px 消息高度。以上是目标，尚未测量；长输入/引导队列单独验收可达性，不套用空输入高度目标。

## 8. 图片与文档粘贴

### 8.1 输入与准备链

选择文件、Ctrl+V、右键粘贴进入同一附件接入函数。App 将独立 chatAttachments API 传入当前只接收 ChatSessionsApi 的聊天组件。聊天输入框接管所有 paste，并同步 preventDefault、捕获 DOM 文件、纯文本、选区、逻辑目标、revision 与序号；DOM 有文件则直接处理，否则请求原生快照。只走文件或文本一个分支，避免原生默认插入与异步回退叠加。

纯文本按原选区插入一次；异步期间用户已编辑则保留新内容并追加本次文字、给出轻量提示，不能用陈旧选区覆盖。操作按原逻辑目标串行提交，已知粘贴自身的 splice 更新后续锚点。右键对聊天输入框调用注册的唯一处理器，其他文本控件保持原行为；共享 textarea 仍挂载不代表会话没变。

新增主进程附件准备 API，接受受限 Uint8Array，不接受任意源路径。图片校验实际格式并返回现有 ChatImageAttachment；文档返回正文和提取说明。prepare 由 requestId 标识，cancel 仅取消同一窗口 owner 的对应任务。新 IPC 不能先对大 Uint8Array 使用 JSON.stringify 限额，必须先检查字段及实际字节数。

异步前固定项目/会话；新建中尚无 sessionId 时使用本地 creationToken 暂存字节与草稿，onCreated 后迁到新会话再 prepare，不能借旧 active。原生快照只要求当前项目，不要求会话已创建。创建失败保留待重试，取消清理。处理中显示状态并阻止未准备好即发送。会话切换后结果仍归原会话，删除/归档或项目切换后的结果取消并丢弃；不会覆盖新草稿。逐文件失败不清空其他附件，未被后台接收的发送失败恢复原附件，保留后来新增内容。

### 8.2 格式与预算

- 图片：PNG/JPEG/WebP/GIF，单张 2 MiB，最多 16 张；截图回退生成 PNG。预发送缩略图、文件名、大小、移除和错误状态明确可见。
- TXT/MD 及已识别 UTF-8 文本：单文件 64 KiB，严格 UTF-8/BOM 解码，不把二进制当文字。
- PDF：单文件 6 MiB，提取最多 20 页、64 KiB 正文，保留页码；扫描件无正文、密码和损坏分别提示。截断显式显示，不伪装读了全文；此版不加 OCR。
- DOCX：单文件 6 MiB；声明直接依赖 yauzl、saxes，惰性读取 word/document.xml 提取段落/表格文字。最多 2048 个 ZIP 条目、解压累计 32 MiB、目标 XML 实际 8 MiB、XML 深度 128；拒绝加密、重复 document.xml、越界条目、DTD/外部实体。旧 DOC、压缩包和其他二进制明确提示不支持。
- 每次待发附件最多 16 个、原始总量 16 MiB；结合 prompt 131072 字符和已有图片数量约束检查总预算。超长正文显示具体截断范围，并让用户审阅，不静默丢弃原草稿。

PDF/DOCX 在可终止 Worker 内解析，10 秒超时、最多 2 并发、队列最多 16、128 MiB Worker heap，并限制实际输出。用户取消或项目退出终止对应 Worker。源码临时运行、桌面编译、Hub 资源准备均接入 worker 入口；Hub 路径通过 hub-workspaces 的 DesktopSharedServices 传到真实 controller，资源 smoke 实际启动 Worker 提取正文。当前只写计划不执行这些构建。

### 8.3 Windows 原生剪贴板回退

仅由用户显式粘贴触发，IPC 不接受路径。DOM File 优先；原生先识别明确 FileNameW 格式中的一个 UTF-16 文件路径，验证普通本地文件并按格式/大小读取，确无文件表示才读取 clipboard.readImage，避免 PDF/DOCX 的预览位图遮蔽原文件。截图先检查空图/像素上限，再编码并检查字节限制；无效文件表示报错，不悄悄改添缩略图。不从普通文字猜路径，不读取 UNC/设备或链接。原生仅返回受限 bytes、text、notices 快照，解析统一经过 prepare。

FileNameW 只作为单文件回退，不能声称完整导入多选。DOM 提供多个 File 时和附件选择器支持多文件；系统仅提供单文件格式时显示该范围。此版不增加 native addon 或 PowerShell 剪贴板进程。

### 8.4 与模型、历史的关系

图片继续走现有 prompt+images，三协议保持真实 vision 载荷；vision:false 时提前提示选择可看图模型并保留草稿。文档在准备成功后将真实正文放入用户消息，模型不能仅收到“附件已添加”占位。useChatSessions 的 send/stageDraft 显式接收同一提交快照并调用唯一 composePrompt，不能只读旧 draft.text；服务器 draftRevision 仍来自原草稿 persist 的返回值。引导队列保存合成正文，恢复时不另添重复文档卡片。

不建立永久附件仓库，不把临时媒体 URL 当模型输入。发送前可预览图片；发送后沿现有历史策略保留文字说明而不新增原始图片持久化格式。文档提取正文作为普通消息保存。新特性不得破坏原会话、guidance 和导出恢复语义。

## 10. 后续补充：Monitor 与停止卡死

用户指定“一页永恒”项目后，实际发现安装版会话卡在 Monitor cancel：父 shell 已退出而游戏持有输出管道，旧清理跳过进程树并无限等待 close。救援先保存会话、核对进程身份，只关闭该项目游戏窗口，保留编辑器；源码修复随后验收。

Windows 使用内核 Job Object 保持完整子树所有权：目标 suspended 创建、分配 Job 后恢复，关闭 Job 自动终止所属子孙。停止等待有界，不能按名称或端口批量结束外部实例。会话取消及时持久化，旧初始化、能力更新、提问、工具回调和完成持久化均检查信号及运行身份，不能覆盖新一轮。

Monitor 默认增量读取，相同命令运行中返回现有作业；restart 必须匹配本会话作业与原命令并经过现有审批。外部实例占用立即说明。连续无变化先提示延长 poll 等待；同一 running/stopping 作业至少实际持续120秒且五次无进展才结束重复轮询。进展、作业/状态切换或其他工作重置预算；最终边界继续消费已受理引导。停止重复轮询不等于确认后台进程已关闭。

实际实施还增加了 Electron `text/uri-list` 文件剪贴板兼容、IPC/附件 pre-await 所有权撤销，以及620px窄视口顶部工具栏换行修复。复杂异步故障由确定性回归覆盖，真实源码窗口验证媒体、剪贴板、模型正文及 Hub 模块双窗，正式安装包验收仍需明确打包请求。
