# SpecLoom 0.1.9 体验改进设计

> 2026-10-18 用户进一步澄清：“思考片段”应为公开过程说明气泡。下文保留原设计记录，展示细则由 [公开进度气泡修正](2026-10-18-progress-bubbles-design.md) 更新；供应商推理改为默认折叠的可选详情。

用户在本轮收集三组反馈并授权开始修改。范围为导航空间、Windows 命令编码，以及聊天过程和文件成果的可见性。延续当前未提交的 0.1.8 源码，不回滚既有改动，不打包发布。

## 选择的展示方式

采用“简短过程默认可见、完整内容按需展开”。只保留总状态会继续隐藏进度；完全展开所有参数与输出会占满聊天高度。因此保留少量最新步骤、实际返回的思考片段、正在编辑的文件与简短结果，提供完整工具链和侧栏入口。用户仍可收起详情；不编造供应商未返回的思考或虚构完成百分比。

项目信息移动到左侧导航的紧凑项目区域。项目名始终易于定位，展开后可见路径、引擎和场景；收起导航时使用图标和可访问名称。窄窗抽屉与导航展开保持一致，不在主内容区继续保留一条顶栏。

## Windows 命令通道

Node 和 PowerShell 监督进程之间显式约定 UTF-8 输入、输出和错误输出。PowerShell 子命令同时配置 UTF-8；cmd 配置 UTF-8 代码页。保持原命令及实参作为数据传递，避免通过字符串拼接重新解释中文、引号、反斜杠。对仍使用系统代码页的本机程序使用有界的流式解码兼容，不把任意损坏字节默认为正常文本。继续保留受管 Job Object 的所有权和有界停止行为。

验证必须包含实际 Windows 进程：中文 stdout/stderr、中文工作目录和参数、cmd/PowerShell、Monitor 启停，以及多字节字符分块。

## 编辑过程与结束清单

编辑时从已验证的工具参数和状态显示文件路径及操作，成功后显示简短结果。失败与仅读取不能计为成功修改。

每次运行结束后在最终回复旁保留本次文件变化清单，支持普通会话和关联任务。按运行标识持久化，继续会话、导出导入和重载后不把上轮文件混入新一轮。对 Write/Edit 记录直接工具证据；对 Bash/code_execution 等命令路径采用运行前后的有界项目文件比较补全。比较基于内容，排除运行前已有脏状态；无变化的写入不计入修改。同名文件去重，区分新增、修改和删除。

文件比较排除 .git、.godot、.specloom 等内部目录及常见依赖与构建目录，不跟随链接。限制数量、字节和时间；无法完整检查时明确标注覆盖范围。命令期间观测到的变化不能断言都由智能体造成。取消或报错也应保留已经确认的修改，不能阻塞停止。

## 验收与限制

- 主工作区不再被 project-bar 占用一行，宽窄窗口导航可用。
- 中文进程输出可读，中文参数与路径完整传递。
- 运行中的步骤与编辑文件适量可见，最新过程不会长期藏在旧滚动位置。
- 每次运行结束有文件清单，失败、不变、跨轮和取消场景正确；扫描受限时不虚报完整。
- 定向单元与集成测试、类型检查、修改文件 lint、源码 Electron E2E 全部验证；随后运行全量测试检查回归。
- 保留既有未提交文件；不打包、提交或替换安装版。源码开发服务可能因主进程修改自动重载，不关闭用户的 Godot 编辑器或游戏。
