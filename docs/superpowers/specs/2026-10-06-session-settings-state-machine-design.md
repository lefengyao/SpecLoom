# 会话设置与实体状态机

用户要求会话设置放在左侧各会话条目内，并确认状态机采用状态和转换表单。

- 每个会话标题右侧提供设置图标，在该条目内展开名称、归档、导出和删除。设置针对该会话，打开或修改其他会话不切换当前聊天，也不影响草稿；运行中会话禁止归档和删除。
- 实体增加可选 `stateMachine` 配置：`initialState`、`states`（id/title/description）和 `transitions`（from/event/to）。从一个待机状态开始，表单可以添加、编辑和删除状态与转换。重命名状态 ID 同步引用；删除状态同步清理相关转换，初始状态调整到剩余状态。至少保留一个状态。
- 初始状态和转换端点必须存在，状态 ID 唯一，同一状态的同一事件最多一个转换。保存与智能体使用同一有界 schema，非法源码也不能绕过校验。状态机配置仅用于实体。
- 项目初始化补充 `specs/components/state_machine.md`，名称“状态机基类”，分组“基础组件”，提供 enabled 和 current_state 字段及进入／更新／退出的行为契约。采用现有仅新建文件的机制，重复打开不覆盖用户修改。
- 添加实体状态机时复用该组件的默认值并挂载一次；状态配置存于实体 Markdown/YAML，其他字段、正文与绑定保留。该配置描述游戏行为，SpecLoom 本身不运行游戏状态机。
- 专用 MaterialCreate/MaterialUpdate 支持 stateMachine，null 清除；实际模型、任务和版本保护沿用现有规则。

保留既有工作树、当前用户项目和未保存草稿。使用临时项目与独立 Electron 验收，不触碰正在运行的开发窗口内用户内容。
