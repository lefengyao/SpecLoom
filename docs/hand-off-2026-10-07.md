# SpecLoom 交接文档

更新时间：2026-10-07  
当前版本：`0.1.1`  
当前分支：`feat/specloom-mvp`

本文用于把当前工作区交给下一位开发者或下一轮智能体继续维护。工作区存在大量未提交修改，接手时不要使用 `git reset --hard`、`git checkout --` 或批量清理命令；先阅读本文件和 `git status`，再针对目标文件修改。

## 项目定位

SpecLoom 是一个 Windows Electron 桌面工作区，面向 Godot 优先的项目开发流程，也支持普通代码项目。它把项目资料、会话、模型供应商、Skills、MCP、离线文档和验证工具放在同一个工作区中。应用版本由 `package.json` 的 `version` 提供，`src/shared/version.ts` 读取该值，顶部导航和“关于项目”页显示同一版本号。

主要入口：

- 主进程：`src/main/main.ts`、`src/main/ipc.ts`、`src/main/preload.ts`
- 桌面控制器：`src/main/desktop-controller.ts`
- 会话运行：`src/main/desktop-sessions.ts`、`src/main/core/session-runs.ts`
- 渲染器入口：`src/renderer/App.tsx`
- 共享契约：`src/shared/`
- 项目说明：`README.md`、`docs/architecture.md`、`docs/tool-workset.md`、`docs/mcp.md`

## 启动与构建

开发环境需要 Node.js 22.12+、npm 和 Windows 桌面环境。首次进入工作区后运行：

```powershell
cd "E:\生产项目\项目\TrailblazerStation\SpecLoom"
npm install
npm run dev
```

`npm run dev` 会启动开发服务器和 Electron，端口由启动脚本自动选择。常用检查命令：

```powershell
npm run typecheck
npm test -- --fileParallelism=false
npm run lint
npm run test:e2e
```

生产构建命令如下：

```powershell
npm run build:app       # 只生成应用资源
npm run build:dir       # 生成未安装目录
npm run build           # 生成安装包和便携 ZIP
```

打包输出按版本写入 `release/<版本号>/`。当前版本的预期产物名称为 `SpecLoom-0.1.1-Setup-x64.exe` 和 `SpecLoom-0.1.1-Portable-x64.zip`。图标构建由 `npm run build:icons` 自动调用；首次构建可能需要先运行 `npx playwright install chromium`。

## 已完成模块

### 会话与回复详情

- 支持会话新建、切换、改名、归档、恢复、删除、导入和导出。
- 会话按项目保存在 `.specloom/history/sessions/`，应用重启会恢复历史；重启时仍处于运行或等待状态的会话会被标记为 `interrupted`。
- 删除带任务历史的会话会保留任务审计所需的删除标记，不会删除项目文件。
- 输入框支持 Enter 发送、Shift+Enter 换行和可选的 Ctrl/⌘+Enter 发送。会话创建和能力扫描异步进行，创建后输入框可以立即输入；切换或新建会话时会主动恢复焦点。
- `hideAgentDetails` 默认开启。思考内容和工具调用收进助手回复气泡顶部，可展开查看。
- 助手消息持久化响应统计：首字耗时、思考时长、输出 token、输出速率和总耗时。重新打开会话仍可显示这些数据。
- 个性化设置可以分别关闭输出速率、首字耗时和思考时长。

相关文件：`src/renderer/chat/ChatTimeline.tsx`、`src/renderer/chat/ChatWorkbench.tsx`、`src/shared/chat.ts`、`src/main/core/session-runs.ts`。

### 工具中心、离线文档与 Hooks

工具区域目前包含离线文档、Hooks、工具说明、归档会话和关于项目页面。

- 离线文档支持选择多个文件或一个本地目录导入，按文档包和版本号管理。
- 文档保存在 Electron 用户数据目录的 `offline-documents/`，不会写入项目目录；启用后所有项目和会话都能按需读取。
- 支持文本、代码、配置、图片、PDF 和其他二进制文件。文本文件可直接读取，二进制文件返回受限的文件信息；导入过程会校验路径、符号链接、文件数量和大小。
- 每个文档包可以选择当前版本、启用/停用、删除单个版本或删除整个文档包。
- Hooks 支持 `session.before`、`session.after`、`tool.before`、`tool.after`。Hook 以本地命令运行，JSON 从标准输入传入；可以配置超时、启用/停用、测试和删除。
- Hook 失败会记录结果，但不会阻断主会话或工具主流程。
- 工具说明页展示搜索工具、加载参数、执行工具、接收结果和继续推理的调用流程，并列出内置及当前会话发现的动态工具。
- 归档会话页支持恢复、导出和永久删除当前项目的归档会话。
- 关于项目页展示项目名称、路径、描述、引擎、Godot 特性、主场景和 SpecLoom 版本。

相关文件：`src/main/core/offline-documents.ts`、`src/shared/offline-documents.ts`、`src/main/core/hooks.ts`、`src/shared/hooks.ts`、`src/renderer/ToolsViews.tsx`。

### 项目文件与 Godot 支持

- 项目文件树位于“项目文件”栏目左侧。
- Godot 项目会过滤 `.godot/` 和 UID 相关内部文件，避免把编辑器缓存和 UID 文件当作用户资料展示。
- 可预览的图片会在项目文件浏览器中提前渲染；普通文本和 Markdown 仍可进入编辑器。
- 资料、组件、设定、地图、UI 和规范继续通过 `ProjectCore`、版本令牌和引用校验保存。

相关文件：`src/renderer/MaterialExplorer.tsx`、`src/renderer/MaterialImage.tsx`、`src/main/core/project-documents.ts`、`src/main/core/file-store.ts`。

### Skills

- 全局 Skill 库位于 Electron 用户数据目录的 `skills/`，索引为 `skills/index.json`，内容位于 `skills/packages/<skill-id>/`。
- 会话 Skills 页面提供本地目录导入、启用/停用和卸载。主进程与 IPC 另有 ZIP 归档导入接口；归档会校验路径穿越和符号链接，当前安装面板尚未提供 ZIP 选择入口。
- 全局 Skill 支持启用、停用、刷新和卸载。
- 项目级 Skill 位于当前项目的 `.specloom/skills/<skill-id>/`，后端提供单独安装、启用、停用和移除接口，状态记录在 `.specloom/skills/.state.json`；项目级管理仍需补充完整界面。
- 已启用的全局 Skill 会在项目打开时复制到项目的 `.specloom/skills/`，目标已有 `SKILL.md` 时跳过。更新、停用或卸载全局 Skill 不会自动更新或删除已复制的项目副本；会话能力发现从项目中的真实 `SKILL.md` 读取版本。

当前安装器要求 `SKILL.md` 使用以下 YAML 元数据，校验为严格模式，不能直接导入仅含 `name`、`description` 的第三方 Skill：

```markdown
---
id: example-skill
name: 示例技能
purpose: 说明技能用途
allowedSources:
  - "specs/**"
---

在这里编写执行步骤。
```

相关文件：`src/main/core/skill-store.ts`、`src/shared/skill-management.ts`、`src/renderer/SessionSkillsView.tsx`、`src/renderer/SkillsView.tsx`。

### MCP

- 全局配置位于用户数据目录的 `mcp.json`。
- 当前项目配置位于 `.specloom/mcp.json`，项目配置只能由当前打开项目编辑。运行时仅在该文件不存在时回退到项目根目录的 `.mcp.json`；两份项目配置不会合并。项目同名服务覆盖全局服务。
- 配置格式为标准 `mcpServers`，运行时支持 stdio 和通过 HTTP(S) 使用的 Streamable HTTP；配置中的 `http` 类型也使用 Streamable HTTP，尚未实现旧式 SSE 传输。
- MCP 页面支持保存、删除、启用/停用和连接测试；服务列表不显示 headers/env 的值，但管理 API 会将完整配置返回 renderer。外部 MCP 凭据当前以明文保存在配置 JSON 中，不受模型凭据的 `safeStorage` 加密保护。
- “测试连接”仅进行最多 5 秒的 HTTP HEAD 探测或命令启动检查；会话能力清单中的“已连接”才表示完成 MCP 初始化和工具发现。HTTP HEAD 不受服务支持时，探测失败不一定表示 MCP 不可用。
- 会话启动时发现全局和项目 MCP 工具；工具定义按需通过 `ToolSearch` 加载，调用超时后保留取消能力。
- 应用自身的入站本机 MCP 服务仍用于外部客户端访问受控的审查工具，地址和令牌每次启动更新。

相关文件：`src/main/core/mcp-config-store.ts`、`src/shared/mcp-config.ts`、`src/main/core/tools/mcp-client.ts`、`docs/mcp.md`。

### 模型请求与等待超时

为减少长任务被误判为超时，当前边界如下：

- 模型配置允许的最大请求时间：`900000 ms`。
- 默认模型请求时间约 `600000 ms`。
- Bash、JavaScript/Python 默认命令超时约 `600000 ms`，仍可由工具参数覆盖。
- MCP 连接和工具发现使用 `30000 ms`。
- MCP 工具调用使用 `600000 ms`。
- Godot 截图、桌面操作和 Hook 使用各自更短的局部上限。
- 所有长操作仍保留 `AbortSignal`，停止会话时会取消模型、MCP、进程和能力发现。

关键常量和入口：`src/shared/contracts.ts` 的 `MAX_MODEL_TIMEOUT_MS`、`src/main/core/agent-client.ts`、`src/main/core/tools/processes.ts`、`src/main/core/tools/mcp-client.ts`、`src/main/desktop-sessions.ts`。

## 持久化路径速查

`userData` 是 Electron 的 `app.getPath("userData")`，Windows 下通常位于 `%APPDATA%` 对应的应用目录，实际位置以运行环境为准。

| 数据 | 路径 |
| --- | --- |
| 全局偏好 | `<userData>/preferences.json` |
| 模型和供应商凭据 | `<userData>` 下的模型/供应商存储，由 `safeStorage` 加密 |
| 全局 Skills | `<userData>/skills/index.json`、`<userData>/skills/packages/` |
| 离线文档 | `<userData>/offline-documents/index.json`、`<userData>/offline-documents/bundles/` |
| Hooks | `<userData>/hooks.json` |
| 全局 MCP | `<userData>/mcp.json` |
| 项目 MCP | `<project>/.specloom/mcp.json` |
| 项目 Skills | `<project>/.specloom/skills/` |
| 项目 Skills 启用状态 | `<project>/.specloom/skills/.state.json` |
| 会话历史 | `<project>/.specloom/history/sessions/` |
| 项目提示词 | `<project>/specs/prompts/system-prompt.md` |

凭据、离线文档和全局配置不应复制进 Git 仓库。项目 `.specloom/skills/` 和 `.specloom/mcp.json` 是否提交，应按项目自己的保密要求决定。

## 接手后的推荐检查顺序

1. 查看 `git status --short`，确认当前已有修改，不清理无关文件。
2. 运行 `npm run typecheck`，先修复编译级问题。
3. 运行 `npm test -- --fileParallelism=false` 和 `npm run lint`。
4. 需要桌面回归时运行 `npm run test:e2e`；测试会直接启动源码，不读取既有打包产物。
5. 修改 UI 后重点回归：新建会话后立即输入、删除会话后重新输入、切换会话焦点、能力扫描未完成时输入、回复详情展开/收起、归档恢复、离线文档导入和 MCP 连接测试。
6. 用户明确要求打包时再运行 `npm run build`，并核对 `release/0.1.1/` 或新版本目录中的安装包、便携 ZIP 和版本号。

## 已知限制与后续待办

- 当前工作区有大量未提交修改，不能把本次交接文档当作干净分支基线。
- 导航栏和工作区的独立滚动上下文仍需在真实窗口中复核。现有审查指出 `.application-shell`、`.application-sidebar`、`.application-body` 和 `.main-content` 的高度与 `overflow` 约束需要统一，避免页面退化为一个全局滚动条。
- MCP 外部服务的认证、网络可达性和工具协议仍依赖用户环境；连接测试成功只代表启动或 HTTP 探测成功。
- Skills 的 ZIP 与项目级接口尚需完整界面接入；第三方常见 `name`/`description` 元数据格式仍需适配。全局 Skill 到项目的复制不包含后续升级或撤销同步。
- 离线文档当前按全局范围启用，尚未提供按项目或按会话的启用范围。
- 二进制离线文档可以保存和识别，但不是所有格式都能在应用内直接预览；PDF 的完整页面渲染仍应单独回归。
- Hook 失败不会阻断主流程，若后续需要强制门禁，应增加独立的失败策略字段和 UI 说明。
- 打包前仍需确认全量测试、lint、typecheck 和 `npm run build` 都以退出码 0 完成，并检查最终安装包中的版本号与图标。
