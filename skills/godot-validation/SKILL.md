# Godot 验证流程

1. 读取任务验收条件、相关实体、当前实现及 specs/prompts/ 中的验证模板，记录来源版本令牌。确认验证针对实际提交版本或明确的暂存快照。
2. 先检查 Markdown/YAML 必填字段、唯一 id、类型、实体关系和任务输入，再检查场景与脚本的资源路径、节点路径、信号和公开接口。
3. 检查单脚本不超过 300 行、每批场景最多 48 节点、复杂子场景最多 24 节点，或已批准的更低预算。检查节点布局、Control 锚点与容器、变换和命名与规范一致。
4. 通过已配置的专用 Godot 验证工具执行无头导入与脚本解析；任务声明 smoke 场景时再执行该场景并检查退出状态和输出。
5. 缺少 Godot 可执行程序或验证后端时明确记录 skipped 与原因，不把未执行检查标为通过。超时、非零退出、解析错误或验收失败均保留原始诊断。
6. 输出逐项 pass、fail 或 skipped，附路径、行列、诊断码、消息、实际命令结果及来源凭据。仅在必需检查通过后报告任务验证通过。
7. 来源在验证期间或提交前变化时使本次结论失效，重新读取并重跑受影响检查。修复仅针对已授权路径和已批准行为。

## 执行边界

验证工具由独立的程序边界控制，本 Skill 不授予 shell 权限。测试规范和验证模板保留在来源文件，不在 Skill 中复制项目特定预期值。
